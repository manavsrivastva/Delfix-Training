==================================================
MODULE 2 - TOPIC 5: VIRTUAL DATABASES (VDBs)
==================================================

--------------------------------------------------
1. WHAT IS A VDB?
--------------------------------------------------
A Virtual Database (VDB) is a database provisioned from either a dSource
or another VDB. It is a full read/write copy of the source data. To end
users, VDBs act and perform just like a standard database.

--------------------------------------------------
2. COMPONENTS
--------------------------------------------------
1) Datasets Page
2) Provisioning

--------------------------------------------------
3. UNDOING AN ACCIDENTAL REFRESH
--------------------------------------------------
An accidental refresh of one or more VDBs from a source database can
remove important data. To correct this, users can use the UNDO VDB
REFRESH or REWIND actions.

--------------------------------------------------
4. ENABLING AND DISABLING VDBs
--------------------------------------------------
* Disabling a VDB is a prerequisite for procedures such as VDB migration
  or upgrade.
* Disabling a VDB removes all traces of it, including configuration files,
  from the target environment it was provisioned to.
* The VDB itself and its metadata still EXIST on the engine.
* When ready to re-enable, the menu shows "Enable" instead of "Disable".
  Once enabled, the VDB continues to function as it did previously.

--------------------------------------------------
5. DELETING A VDB
--------------------------------------------------
* Deleting a VDB is an UNRECOVERABLE operation. Proceed only if you want
  to permanently destroy the unique data created in the VDB.
* You cannot delete a VDB that has dependencies, because the dependencies
  rely on the data associated with the snapshot.
